# First Production UAT — Live $1 Stripe + Real Twilio Number

Prepared 2026-06-07. Goal: run ONE end-to-end formation through the **live**
production path for ~$1, provisioning a **real** US phone number, to prove the
paid pipeline before opening to real customers.

---

## What's already built (this session)

1. **`DEMO_DOLLAR` $1 override** — `src/app/api/create-checkout-session/route.ts`.
   When `DEMO_DOLLAR=1` **and** the signed-in email is in `DEMO_DOLLAR_EMAILS`
   (comma-separated, or `*` for any signed-in user), the whole cart collapses to
   a single **$1.00** line item. Off by default; if the flag is on but the email
   isn't allowlisted it **fail-safes to full price** (and logs a warning).
   Doc generation + phone provisioning are unaffected (they key off metadata,
   not the line items).

2. **Real Twilio number in the UAT** — `scripts/e2e-uat-edge-variants.mjs`.
   When `UAT_FORWARD_PHONE_E164` is set, the harness requests `business_phone`
   and passes that forward-to number, so the webhook provisions a **real** US
   number (Florida → area code 305/786). Unset → identical to before (no phone).

3. **Removed the silent test-key fallback** in the checkout route. It now throws
   if `STRIPE_SECRET_KEY` is missing instead of quietly using a baked-in
   `sk_test` key (which would let "successful" live checkouts collect $0).

The webhook (`webhooks/stripe/route.ts`) already reads `STRIPE_SECRET_KEY` /
`STRIPE_WEBHOOK_SECRET` straight from env — no test fallback there.

## Go-live steps (once the 3 live values are in hand)

> ⚠️ Pushing to `main` auto-deploys to the client's PRODUCTION. All changes are
> off-by-default, but treat each step deliberately.

```bash
cd /mnt/c/Users/neotr/Documents/AvenidaLegal/CompanyFormationQuestionnaire

# 1. Deploy the prep code (DEMO_DOLLAR override + harness phone + fallback fix)
git push origin main          # Vercel auto-deploys

# 2. Set LIVE Stripe + the $1 demo gate in Vercel production
#    (re-paste each value when prompted; mark sk/whsec as "sensitive")
vercel env rm  STRIPE_SECRET_KEY production --yes
printf 'sk_live_XXX' | vercel env add STRIPE_SECRET_KEY production
vercel env rm  NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY production --yes
printf 'pk_live_XXX' | vercel env add NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY production
vercel env rm  STRIPE_WEBHOOK_SECRET production --yes
printf 'whsec_XXX'   | vercel env add STRIPE_WEBHOOK_SECRET production

printf '1'                  | vercel env add DEMO_DOLLAR production
printf '<uat-test-email>'   | vercel env add DEMO_DOLLAR_EMAILS production   # or '*'

# 3. Redeploy so the new env is live (env changes need a fresh deploy)
vercel --prod

# 4. Run the UAT — ONE variant, real card, real number
#    forward-to = the real cell the new number should ring (E.164, +1…)
export UAT_FORWARD_PHONE_E164='+1XXXXXXXXXX'
export STRIPE_CARD='<REAL card number>'   # harness currently fills 4242; live mode rejects it
node scripts/e2e-uat-edge-variants.mjs 6  # 6 = LLC sole-owner, Florida

# 5. Verify
#    - Stripe live dashboard: one $1.00 paid charge
#    - Dashboard: 6 docs generated + downloadable
#    - Twilio console: one new number (305/786), forwards to UAT_FORWARD_PHONE_E164
#    - Call the new number → rings the forward-to phone
```
